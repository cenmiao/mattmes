# Domain Docs

工程技能在探索代码库时应如何消费本仓库的领域文档。

## 探索前先阅读

- **仓库根目录的 `GLOSSARY.md`**
- **`docs/adr/`**：阅读涉及你即将工作领域的 ADR。

本仓库为**单上下文**布局，不存在 `GLOSSARY-MAP.md`。

如果这些文件不存在，**静默继续**。不要标记其缺失，也不要建议提前创建。

## 文件结构

```
/
├── GLOSSARY.md          ← 领域术语，纯词汇表
├── docs/adr/            ← 架构与业务决策
│   ├── 0001-数据库审计字段规范.md
│   └── ...
├── mattmes/             ← 后端（Spring Boot）
└── mattmes-ui/          ← 前端（Vue 3）
```

## 用术语表的词汇

当输出命名领域概念（问题标题、重构提案、假设、测试名称），使用 `GLOSSARY.md` 中定义的术语。不要漂移到术语表明确列在 `_Avoid_` 下的同义词。

若所需概念尚未收录，这是一个信号：要么你在发明项目不使用的语言（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 术语表只放术语

`GLOSSARY.md` **不是**规格、不是草稿本、不是实现决策的存放处。业务规则、接口契约、设计 token 属于 ADR，不属于术语表。新增内容前先判断：这是本上下文特有的**概念**，还是实现细节？只有前者进术语表。

## 标记 ADR 冲突

若你的输出与现有 ADR 矛盾，显式提出而不是静默覆盖：

> _与 ADR-0009（领域业务规则）中的删除约束矛盾 —— 但值得重新开启，因为……_
