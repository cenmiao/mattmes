# 0009-领域业务规则

## 状态

已接受

## 背景

本仓库的领域术语由 `GLOSSARY.md` 承载，但术语背后的**约束规则**（谁能引用谁、什么状态禁止什么操作、流转如何判定）不属于术语表，也不适合散落在各处 PRD 里。此 ADR 集中记录这些跨模块的领域规则，作为实现与评审时的唯一依据。

## 决策

### 1. 主数据层级

```
项目 (1:N) 料号 (N:1) 路由 (1:N, 有序) 工序
```

- 一个项目包含多个成品料号，一个料号只属于一个项目。
- 多个料号可共用同一个路由；一个料号只能绑定一个路由（N:1）。
- 路由由**有序**工序序列构成，工序之间定义"下一步去向"。

### 2. 主数据约束

| 对象 | 规则 |
|------|------|
| 料号创建 | 必须关联一个存在且**启用**的项目 |
| 料号编码 | 全局唯一，创建后不可修改 |
| 料号所属项目 | 创建后不可修改 |
| 料号删除 | 已有路由绑定或工单时禁止删除 |
| 项目禁用 | 不联动已存在料号的状态，但新料号无法关联已禁用项目 |

### 3. 实施顺序

依赖关系决定了开发顺序，后项不得先于前项：

1. **主数据**：工序 → 项目 → 料号 → 路由
2. **业务单据**：工单（依赖料号） → SN（依赖工单）
3. **业务执行**：过站（依赖 SN、工序、路由）

### 4. SN 与路由的继承

路由沿 `料号 → 工单 → SN` 逐级继承。SN 生成时自动取得路由（工单 → 料号 → 路由），初始"下一工序"即路由的第一道工序。所有 SN 必须按路由定义的工序顺序生产。

### 5. 过站流转

- 流转类型有两种：**线性顺序**（A→B→C→D）与**分支选择**（A→B→C→返回 B 或直跳 D）。
- SN 必须按路由定义的流转关系过站，**不可跳过中间工序**。
- 每次过站生成一条过站记录，同时更新 SN 的"下一工序"字段，指向下一个要去的工序。

### 6. 账户与登录规则

| 规则 | 阈值 |
|------|------|
| 密码强度 | 至少 8 位，必须包含字母 + 数字 |
| 首次登录 | 强制修改密码 |
| 密码过期 | 每 30 天必须修改 |
| 登录错误锁定 | 连续错误 5 次，锁定 10 分钟 |
| 自动禁用 | 连续 30 天未登录则账户自动禁用，管理员可手动恢复 |

禁用原因区分 `ADMIN_MANUAL`（管理员手动禁用）与 `AUTO_INACTIVE`（30 天未登录自动禁用）。

### 7. 并发登录

同一用户同一时间只能在一个终端登录。新登录检测到已有会话时返回 `409` 供前端确认，用户确认后覆盖旧 Token 使旧设备失效。并发场景依赖数据库事务锁保证只有一个请求成功，不使用 Redis。

Token 立即失效的三种情形：用户被禁用、用户修改密码、他处强制登录。

### 8. 超级管理员

默认账号工号 `admin`，默认角色 `SUPER_ADMIN`，自动拥有全部权限且后端拦截器对其跳过权限校验，前端禁止删除或禁用该账号。

## 理由

这些规则跨越多个模块且部分只在代码中体现（如 `LoginServiceImpl` 的 30 天/5 次阈值），如果只留在代码里，新的实现者容易写出不一致的分支。集中记录后，评审时可以直接对照，不必反查实现。

## 影响

- 新增基础数据模块应复用同一套约束，见 ADR-0008。
- 数据库审计字段规范见 ADR-0001。
- Token 存储与并发控制的技术选型见 ADR-0002。
