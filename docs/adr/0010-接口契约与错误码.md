# 0010-接口契约与错误码

## 状态

已接受

## 背景

前后端分离架构下，所有接口需要统一的响应外壳和一套稳定的错误码，否则前端无法集中处理认证失效、权限不足和并发冲突。此 ADR 记录这份契约。

## 决策

### 统一响应格式

所有接口返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { }
}
```

### 标准错误码

| 错误码 | 说明 | 触发场景 |
|--------|------|---------|
| 200 | 操作成功 | 正常业务响应 |
| 400 | 业务异常 | 参数错误、密码强度不足、用户名不存在等 |
| 401 | 认证失败 | Token 无效、Token 过期、被强制登出 |
| 403 | 权限不足 | 无该接口访问权限 |
| 409 | 业务冲突 | 账号已在其他设备登录（等待用户确认强制登录） |
| 500 | 系统异常 | 后端代码异常 |

### 被强制登出（401）

```json
{
  "code": 401,
  "message": "您的账号已在其他设备登录，请重新登录",
  "data": null
}
```

### 账号在其他设备登录（409）

```json
{
  "code": 409,
  "message": "账号已在其他地方登录，是否强制登录？",
  "data": {
    "currentLoginTime": "2026-05-30 10:30:00",
    "currentLoginIp": "192.168.1.100"
  }
}
```

`data` 携带上次会话的时间与 IP，供前端在冲突弹窗中展示。

## 理由

`409` 与 `401` 都涉及登录态，但语义完全不同：`409` 是"可以强制登录"的可恢复冲突，`401` 是"当前凭据已作废"。用不同状态码区分，前端才能在不解析 message 的前提下选择弹窗还是跳转登录页。

## 影响

- 前端响应拦截器据此分流处理，见 ADR-0003。
- 后端新增接口必须复用该外壳，不得直接返回裸对象。
