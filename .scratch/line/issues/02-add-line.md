# 02: 新增线体

**What to build:** 管理员能通过新增弹窗录入一条线体，提交后列表立即出现该记录。这一票承载全部新增期校验，是后续编辑、状态、删除、导出四票的共同前置。核心风险点是编码唯一性：逻辑删除会让默认查询忽略已删除记录，若只查未删除数据，删除某编码后再用同一编码新建会撞上数据库唯一索引并抛出 500，因此查重必须连同已删除记录一起统计，冲突时返回 400 与明确提示。

**Blocked by:** 01 (线体建表与只读列表)

**Status:** ready-for-agent

- [ ] 新增接口接受编码、名称、描述、初始状态，返回新记录 ID
- [ ] 编码必填，为空或纯空白返回 400
- [ ] 名称必填，为空或纯空白返回 400
- [ ] 编码长度超过 50 返回 400，名称长度超过 100 返回 400
- [ ] 编码只允许字母、数字、下划线、中划线，其他字符返回 400
- [ ] 编码与已存在（未删除）记录重复时返回 400，提示"线体编码已存在"
- [ ] 编码与已删除记录重复时同样返回 400，不落入数据库唯一键异常
- [ ] 未传状态时默认为启用
- [ ] 新增成功后列表刷新可见该条记录
- [ ] 弹窗内前端校验与后端规则一致（必填、长度、编码格式），校验不通过不发起请求
- [ ] 新增按钮仅在拥有 `line:add` 时渲染
- [ ] 后端集成测试覆盖上述校验分支，且通过 HTTP 层断言而非直接调用服务
