# 线体（Line）管理

Status: ready-for-agent

## Problem Statement

MES 系统当前只有**工序**这一种生产资源主数据，没有任何对象描述"生产在哪个物理产线上发生"。工序、项目、料号、路由都定义完了，但车间现场的实际生产单元——线体——在系统里不存在。

这带来两个具体问题：

1. **无法登记产线**：管理员拿到一条新产线时，没有任何界面可以把它录入系统，也没有编码可以引用它。
2. **无法按产线组织生产**：由于线体不存在，后续的工单排产、SN 归属、过站记录都无法标注"哪个线体做的"，产线维度的产能与追溯分析无从开始。

用户需要的是一条与工序同等级的基础数据：能建、能改、能停用、能删除、能导出，字段最小但有编码有名称有描述有状态。

## Solution

新增**线体管理**模块，作为独立的基础数据（主数据），行为与现有的工序管理完全同构：

- 一个列表页，支持按线体编码、线体名称模糊查询，按启用状态筛选，分页展示。
- 支持新增（编码 + 名称 + 描述 + 状态）、编辑（编码不可改）、单条删除、批量删除、列表内直接切换启用/禁用。
- 支持按当前查询条件导出 CSV。
- 权限与其他主数据一致：查看、新增、编辑、删除、导出五个独立权限点，未授权不可见对应按钮。

线体在本期是**孤立的主数据**：不与工序、路由、工单、SN 建立任何绑定关系。这保证本期交付范围可控，同时为后续"工单绑定线体"预留干净的扩展点。

## User Stories

1. 作为生产管理员，我想在菜单里看到"线体管理"入口，这样我能找到产线维护功能。
2. 作为生产管理员，我想分页浏览所有线体，这样线体多了也不会页面卡死。
3. 作为生产管理员，我想按线体编码模糊搜索，这样我能快速定位某条已知编号的产线。
4. 作为生产管理员，我想按线体名称模糊搜索，这样我记不住编码时也能找到产线。
5. 作为生产管理员，我想按启用状态筛选线体，这样我能只看当前在用的产线。
6. 作为生产管理员，我想组合使用编码、名称、状态三个条件查询，这样我能精确缩小结果范围。
7. 作为生产管理员，我想一键重置查询条件，这样我不必手动清空每个输入框。
8. 作为生产管理员，我想新增线体并填写编码、名称、描述、初始状态，这样新产线可以录入系统。
9. 作为生产管理员，新增线体时编码必须是必填且唯一的，这样不会出现两条编码相同的产线导致现场混乱。
10. 作为生产管理员，新增线体时如果编码重复，我想看到明确的"线体编码已存在"提示，这样我知道该换个编码。
11. 作为生产管理员，删除某条线体后，我希望再用同样的编码新建线体时仍被提示"已存在"，这样不会因为踩到数据库唯一键而收到费解的系统错误。
12. 作为生产管理员，新增线体时编码只能包含字母、数字、下划线和中划线，这样编码在 URL、导出文件和日志里都不会出问题。
13. 作为生产管理员，新增线体时如果编码或名称超长，我想看到具体的长度上限提示，这样我能及时修正。
14. 作为生产管理员，新增线体时如果不填状态，系统应默认为启用，这样我少填一个字段。
15. 作为生产管理员，我想编辑已有线体的名称、描述和状态，这样产线信息变了能及时更新。
16. 作为生产管理员，我想在编辑时看到编码是只读的，这样我不会误以为能改编码。
17. 作为生产管理员，我想在列表里直接用开关切换线体的启用/禁用，这样不用进弹窗改一个状态。
18. 作为生产管理员，切换状态失败时我希望开关自动回弹到原状态，这样界面不会显示与真实数据不符的状态。
19. 作为生产管理员，我想删除单条线体，删除前希望弹确认框并显示线体名称，这样我不会误删。
20. 作为生产管理员，我想勾选多条线体后批量删除，这样清理测试数据时不用一条条删。
21. 作为生产管理员，批量删除前希望确认框显示将要删除的条数，这样我能核对数量。
22. 作为生产管理员，未勾选任何线体时批量删除按钮应处于禁用状态，这样我不会误触。
23. 作为生产管理员，我想按当前查询条件导出线体数据为 CSV，这样我能离线分析或交付给他人。
24. 作为生产管理员，导出的 CSV 用 Excel 打开时中文不应乱码，这样我不需要手工转码。
25. 作为生产管理员，导出的 CSV 里描述字段即使包含逗号、引号或换行也不应错列，这样数据能被正确解析。
26. 作为生产管理员，导出文件名应带时间戳，这样我多次导出不会互相覆盖。
27. 作为生产管理员，列表应显示每条线体的创建人和创建时间，这样我能知道谁什么时候建的。
28. 作为生产管理员，列表描述列过长时应显示省略号并能悬浮查看全文，这样表格不会被撑开。
29. 作为生产管理员，我想看到线体编码的唯一性校验在数据库层面也有兜底，这样并发新增也不会产生重复数据。
30. 作为只读用户，如果我没有"线体查看"权限，我访问线体页面应被拦到 403，这样权限控制是真实的。
31. 作为只读用户，如果我没有"线体新增"权限，我不应看到新增按钮，这样界面不会给我点了会失败的按钮。
32. 作为只读用户，如果我没有"线体编辑"权限，我不应看到编辑按钮和状态开关，这样我不会触发无权操作。
33. 作为只读用户，如果我没有"线体删除"权限，我不应看到删除和批量删除按钮。
34. 作为只读用户，如果我没有"线体导出"权限，我不应看到导出按钮。
35. 作为超级管理员，我应自动拥有全部线体权限，不需要单独授权。
36. 作为系统管理员，我希望线体编码创建后不可修改，因为编码是业务唯一标识，改它会让引用方对不上。
37. 作为系统管理员，我希望线体被删除时只做逻辑删除，这样历史数据可追溯、误删可恢复。
38. 作为系统管理员，我希望线体表带有统一的审计字段，这样符合系统既有数据规范。
39. 作为系统管理员，我希望线体的删除不因"存在关联"被阻止，因为本期线体没有关联数据。
40. 作为开发人员，我想线体的后端接口路径风格与工序保持一致，这样我可以直接对照既有实现做代码审查。
41. 作为开发人员，我想线体的分页响应结构与工序一致，这样前端的请求/响应处理逻辑可以复用。
42. 作为开发人员，我想线体的建表与权限脚本是幂等的，这样在已有环境重复执行不会报错。
43. 作为开发人员，我想线体模块的术语被写进领域词条表，这样后来的人不会造出"产线""生产线"这类同义词。
44. 作为开发人员，我想线体与既有主数据的关系被记录进领域规则文档，这样评审时能直接对照。

## Implementation Decisions

### 数据模型

新增表 `mes_line`，字段：

- `id`：BIGINT 主键自增
- `line_code`：VARCHAR(50)，NOT NULL，唯一索引，创建后不可修改
- `line_name`：VARCHAR(100)，NOT NULL
- `description`：VARCHAR(500)，可空
- `enable`：TINYINT，NOT NULL，默认 1（1=启用/0=禁用）
- 审计字段：`created_by`、`create_time`、`updated_by`、`update_time`
- `deleted`：TINYINT，NOT NULL，默认 0，逻辑删除标记

索引：主键 `id`、唯一键 `uk_line_code`、普通索引 `idx_enable` 与 `idx_deleted`。

**刻意偏差（用户原始字段清单 → 最终方案）：**

- 用户写的是 `desc`，改为 `description`。`DESC` 是 SQL 保留字，作为列名需要全链路反引号转义，会在 ORM 生成 SQL 时持续踩坑。
- 用户写的是 `line_code` / `line_name`，予以保留（符合 ADR-0008 的 `{entity}_code` / `{entity}_name` 命名规范）。
- 用户未提备注字段，因此**不建 `remark` 列**。ADR-0008 的必含字段表中不含 `remark`（虽然其建表模板里带了），且用户两次字段清单均未提及，多加一列等于多一份无人维护的数据。
- 状态沿用全库统一的 `enable` 语义，不另造 `status` 枚举。

### 命名对照

Java 实体、DTO、前端 TypeScript 接口**全链路使用 `lineCode` / `lineName`**，与列名一一对应，靠 MyBatis-Plus 的驼峰映射零注解。先例是 `MesMaterial` 的 `materialCode` / `materialName`。

### 后端接口

统一前缀 `/api/line`，路径风格与工序、项目保持一致（非料号的 RESTful 风格）：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/line/list` | 分页查询，条件放请求体 |
| POST | `/api/line/add` | 新增，返回新 ID |
| PUT | `/api/line/edit` | 编辑，ID 放请求体，编码不接受 |
| PUT | `/api/line/status/{id}?enable=` | 切换启用状态 |
| DELETE | `/api/line/delete/{id}` | 单条逻辑删除 |
| DELETE | `/api/line/batchDelete` | 批量逻辑删除，ID 数组放请求体 |
| GET | `/api/line/export` | 按查询条件导出 CSV |

响应统一 `{ code, message, data }` 包装；分页响应结构为 `{ list, total, pageNum, pageSize }`。

### 业务规则

- 编码：必填，长度 ≤ 50，格式 `^[a-zA-Z0-9_-]+$`（仅字母、数字、下划线、中划线）。
- 名称：必填，长度 ≤ 100。
- 描述：长度 ≤ 500。
- 编码唯一性：新增时**连同已删除记录一起查重**。因为逻辑删除会绕过 MyBatis-Plus 的默认查询条件，若只查未删除记录，删掉某编码后重建会撞上数据库唯一索引并抛 500。需要一条显式忽略逻辑删除的计数查询来兜底。
- 新增时 `enable` 为空默认 1。
- 编辑时编码不被接受（请求体中无该字段），名称、描述、状态可改。
- `enable` 仅允许 0 或 1，其他值返回 400。
- 删除为逻辑删除；**不做关联数据校验**，因为本期线体无任何关联。
- 批量删除先逐条校验存在性，再统一逻辑删除。

### 导出

- 格式 CSV，`text/csv;charset=UTF-8`，文件名带 `yyyyMMdd_HHmmss` 时间戳。
- 列清单：`ID,线体编码,线体名称,描述,启用状态,创建人,创建时间`，共 7 列。审计口径只导创建侧（与工序一致，不导更新人/更新时间）。
- 状态列导出原始值 `1`/`0`，不转中文，避免下游解析脚本对不上。
- **必须写入 UTF-8 BOM（`\uFEFF`）**，否则 Excel 打开中文乱码。这一点与工序现有实现存在行为差异：工序的 CSV 缺 BOM，是既有缺陷，本模块不复制该缺陷，工序的修复另行立项。
- 字段含逗号、双引号或换行时按 CSV 规则用引号包裹并转义内部引号。

### 权限

新增模块级权限 `line` 与五个按钮级权限：`line:read`、`line:add`、`line:edit`、`line:delete`、`line:export`。超级管理员自动拥有，无需显式授权。

前端三层均需配置，**不复制工序的遗漏**：
- 路由 `meta.permission: 'line:read'`
- 菜单项 `permission: 'line:read'`
- 按钮级 `v-permission`

（背景：工序页面在路由和菜单两处都漏配了 permission，而用户、角色、料号三个模块都配了。漏配是缺陷不是约定，新模块不继承。）

### 前端

- 页面路由 `/lines`（复数，符合 ADR-0008 与料号的 `/materials`；工序的 `/process` 单数是历史偏差）。
- 菜单图标用 Element Plus 的 `Connection`（已确认存在并导出，连接/拓扑语义贴合"线体"）。
- 列表页结构与工序列表页同构：查询卡片（编码/名称/状态 + 查询/重置/新增/批量删除/导出）、表格（多选列、ID、编码、名称、描述、状态开关、创建人、创建时间、操作列）、新增与编辑弹窗、分页控件。

### 脚本落点

新建表与权限脚本放在 `mattmes-web` 模块的 migration 目录，编号接在现有 `V3` 之后（`V4` 建表、`V5` 权限）。已有环境的 `V0`~`V3` 不动，`.business` 模块下散落的 `V1`/`V2` 也不动。

全部使用幂等写法（`CREATE TABLE IF NOT EXISTS`、`INSERT ... WHERE NOT EXISTS`），因为项目**没有 Flyway 依赖**，这些脚本是手工执行的，重复执行必须无害。

### 领域文档

- `GLOSSARY.md` 主数据段新增"线体"词条，定义为一个独立存在、本期不与工序/路由/工单绑定的物理产线单元，编码全局唯一且创建后不可修改；`_Avoid_` 列产线、生产线、车间。
- `docs/adr/0009-领域业务规则.md` 的主数据约束表中补一行线体规则，说明其为独立主数据。
- **不新开 ADR**：该决策不难逆转（加关联表即可扩展）、不反直觉（独立主数据是默认做法）、没有真实取舍，不满足开 ADR 的三条判据。

## Testing Decisions

### 什么算好测试

只断言**外部可观察行为**：HTTP 状态码与响应体内容、页面渲染出的元素、点击后触发的 API 调用与参数。不断言私有方法、不断言 SQL 语句、不 mock Mapper 去验证调用次数。一个测试应当"改实现不改行为时不需要改测试"。

### 测试缝隙（两个，均复用既有，不新建）

**缝隙 1：后端 HTTP 层（最高点）**

用 `MockMvc` 直接打 `/api/line/**`，一个缝隙同时覆盖 Controller → Service → Mapper → 建表 SQL 的全部行为。**不再单独写 Service 层单测**——同一批业务规则在 HTTP 层断言一遍即可，写两遍是对实现细节的重复覆盖。

- 先例：`ProcessControllerTest`（`@SpringBootTest` + `@AutoConfigureMockMvc` + `@Transactional`，真实 MySQL，测试结束回滚）
- 覆盖：新增成功；编码重复返回 400；**编码与已删除记录重复也返回 400**；编码格式非法返回 400；编码/名称超长返回 400；必填缺失返回 400；编辑不改编码；编辑不存在的 ID 返回 400；状态切换成功与非法状态值返回 400；单条删除后列表查不到；批量删除；分页与三类筛选条件；导出响应头、CSV 表头 7 列、**响应体以 BOM 开头**、含逗号/引号/换行的描述字段转义正确。

**缝隙 2：前端组件挂载层**

`mount(LineList)` 配合 `vi.mock('@/api/line')`，验证页面可交互行为。

- 先例：`ProcessList.spec.ts`（断言导出按钮存在、点击后调用导出 API）
- 覆盖：页面挂载后触发列表查询；导出按钮存在且点击调用 `exportLine`；传参包含当前查询条件；新增弹窗提交调用 `addLine`；状态开关触发 `updateLineStatus`；删除走确认后调用 `deleteLine`。

### 不采用的缝隙

不 mock Mapper、不写 Service 单测、不测 TypeScript 类型、不测 Java DTO 的 getter/setter。

### 环境约束（重要）

缝隙 1 依赖 `localhost:3306` 的真实 MySQL。当前环境实测：3306 端口不通，MySQL 服务不存在，Docker 守护进程未启动。因此**缝隙 1 的测试代码会交付，但本地无法执行**，交付时必须标注"未执行，需在具备 MySQL 的环境运行"。

缝隙 2 可本地真实执行（`npm run test:run`）。

### 验证清单

本地可验证：后端 `mvn clean compile`、`mvn clean test-compile`；前端 `npm run build`、`npm run test:run`。
本地不可验证：后端两个集成测试的实际通过结果。

## Out of Scope

- **线体与任何实体的关联**：不与工序、路由、工单、SN 建立绑定；删除线体不做关联校验；不提供"按线体查工序/工单"的接口。
- **主数据层级图变更**：ADR-0009 的 `项目 → 料号 → 路由 → 工序` 层级不变。
- **备注字段**：本期不建 `remark` 列。
- **编码变更**：不提供修改线体编码的能力。
- **E2E 测试**：不新增 Playwright/e2e 用例，待真实联调时再补。
- **数据导入**：不提供 Excel/CSV 批量导入线体。
- **排序与拖拽**：不提供线体自定义排序或拖拽排序。
- **线体级联禁用**：不涉及，因本期无线体关联对象。
- **工序导出的 BOM 缺陷修复**：不在本期内顺带修改，另行立项。
- **`created_by` 审计字段填充缺陷修复**：见下节。

## Further Notes

### 两处已知继承缺陷，本期不修

1. **`created_by` 永远为 NULL**：公共模块的审计字段自动填充逻辑只填 `createTime`、`updateTime`、`updatedBy`、`deleted`，**漏了 `createdBy`**，全仓库也没有任何显式 `setCreatedBy` 调用。因此工序、项目、料号表的 `created_by` 至今全是空值，导出的"创建人"列一直是空列。

   本模块**如实继承该现状**：`created_by` 保持 NULL，导出"创建人"列为空。理由：修复需改动公共模块的自动填充逻辑，波及所有模块的写入路径，与本次需求无关，属独立改动。建议另开 issue 跟踪。

2. **工序导出 CSV 缺 UTF-8 BOM**：线体导出会正确带上 BOM，两者行为不同。这是刻意的，不是疏漏。工序的问题另开 issue。

### 视觉与交互一致性

线体列表页应尽量与工序列表页在视觉上一致（同一套卡片、表单、表格、弹窗布局），差异只体现在字段与文案。前端设计 token 见 `docs/adr/0011-前端设计规范.md`，新页面只引用既有 CSS 变量，不新增配色。

### 评审时的对照方式

评审者可以直接拿工序模块（实体 / Mapper / Service / Controller / API 封装 / 列表页 / 测试）作为对照物逐项比对，差异应只有：字段名、无备注字段、无工序类型字段、导出多 BOM、路由和菜单补了 permission。
